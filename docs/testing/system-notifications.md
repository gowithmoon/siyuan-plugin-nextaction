## 真机验收限制与操作步骤

当前会话没有图形桌面或移动设备连接，无法观察 OS 通知中心，也无法执行移动 App 退出/重启。因此桌面及移动端 OS 弹窗均为待验收，不能把平台模拟测试记为真机通过。

部署后重新加载 NextAction 插件（或重启思源），进入“NextAction 设置 → 常规 → 提醒 → 系统通知”。默认关闭。以下步骤在独立临时任务上执行，结束后清理任务并恢复原设置：

1. 桌面 App 开启并保存，创建约 2 分钟后到期、提前 1 分钟提醒的任务；保持思源窗口存活，约 1 分钟后核对通知中心标题与实际到期时间。
2. 在旧触发时间前修改 due；等待经过旧触发时间，确认旧计划没有弹窗，再核对新计划只弹一次。
3. 分别在触发前完成任务、改为 Someday，经过原触发时刻后应无通知。
4. 有未来计划时关闭系统通知并保存，经过原触发时刻应无通知；重新开启后只注册当前未完成任务。页面 Toast 不受该开关影响。
5. 对同一数据连续同步（sync-end）及覆盖同步（overwrite），同一任务、同一触发点只出现一条通知。自动化 lifecycle 测试已有重复事件的幂等覆盖。
6. 移动 App 授予系统通知权限后安排未来提醒并退出 App，在计划时间核对通知；重新打开后修改任务，确认旧 ID 清理和新计划重建。记录 OS、思源版本、权限和电池后台限制。
7. 分别以桌面浏览器和移动浏览器打开设置，确认系统通知开关可见且灰显；保存其他选项，到点仍有页面 Toast。
8. 切换英文／简体中文并重新加载插件，核对设置标题、描述、到期正文和“今日回顾”正文。

平台边界：桌面延迟调度依赖思源窗口定时器，窗口关闭后不保证触发；移动 App 的后台通知由 OS 及系统权限控制。计划视窗为未来 7 天，长期不打开 App 的任务不保证自动扩展视窗。
